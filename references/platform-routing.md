# 平台路由

研究开始前分别检测飞书文档写入、画板写入、画板导出预览、本地文件生成能力。选择真实可完成的最高交付等级。不要仅凭产品名称假设能力存在；“能创建飞书文档”不代表“能创建画板”。

## FEISHU

仅当当前环境存在可调用的飞书文档写入能力且用户身份已授权时使用。

执行顺序：

1. 确认文档写入工具和当前身份可用；
2. 确认能创建画板，或能在飞书文档中插入非空 SVG 画板；
3. 创建标题为“<公司名称>企业与行业研究”的文档，并在“30 秒结论”之后创建画板占位；若不能先写正文，至少先创建画板并保存其 token；
4. 立即保存真实文档链接、画板 token 和后续写入方法；画板 token 不得只留在临时上下文；
5. 开展研究并制作总览图 SVG；
6. 将 SVG 写入预先创建的画板 token。若平台只支持文档内联插入，则在“30 秒结论”之后插入非空的 `<whiteboard type="svg">` 内容；不得保留空白占位；
7. 写入其余报告正文；
8. 回查文档，确认总览图确实位于结论之后且画板内容非空；导出飞书画板预览并查看实际渲染。

只有聊天入口、知识检索能力、能创建普通文档或“原生接入飞书”的产品说明，不等于拥有画板写权限。若文档可以写入但画板能力不确定，先尝试一次在文档中插入非空 SVG 画板并回查；失败后切换到 `FILES`，同时保留已创建的飞书文档链接，并明确指出画板写入失败。对同一步骤最多修复重试两次。

完成 FEISHU 的必要条件是：真实文档存在、正文存在、其中有非空总览画板、能导出且看过飞书实际预览。任何一项缺失都属于降级交付，不得静默省略画板。

## FILES

创建目录 `<company>-research/`，至少包含：

```text
report.md
overview.svg
```

来源较多时增加 `sources.md`；具备可靠 SVG 渲染器时增加 `overview.png`。`report.md` 必须是完整报告，`overview.svg` 必须可独立打开，不得只提供伪路径或代码片段。

## CHAT

在对话中提供完整报告和画板的结构化视觉方案，并明确说明当前环境不能创建飞书文档或本地文件。不得声称已经生成附件、SVG 或在线文档。

## 用户覆盖

用户明确指定交付格式时遵从用户：例如“不创建飞书文档”会覆盖默认 `FEISHU`。用户只指定研究深度而未指定交付格式时，仍按上述能力路由。
